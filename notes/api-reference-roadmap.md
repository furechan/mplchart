# API Reference Roadmap

Status and plan for the API reference docs — human site and agent consumption. Decisions from the July 2026 design discussion.

## Shipped

- `docs/reference/{chart,primitives,indicators,expressions,styles}.md` — generated committed markdown, one page per module, each stamped with a do-not-edit marker. Convention: `docs/reference/` is generated-only, with one exception — the hand-written `reference/index.md` landing page (must live there to be the section index). Hand-written guides live at `docs/` root (`backends.md`); nav placement is independent of file location.
- `scripts/make-api-docs.py` (`inv apidocs`) — griffe-based generator. Static extraction, google docstrings parsed to structured sections, every line of markdown emitted by the script. Built-in render check: each page is parsed with the same markdown extensions mkdocs uses; fails on trapped lists or unbalanced fences.
- Docstring fixes surfaced by griffe's stricter parser (Args `name (type) :` spacing) and module docstrings fleshed out as page intros. `mplchart.primitives` has a curated `__all__` (also the page order).

## Architecture

One pipeline, two audiences: the generator produces committed markdown; mkdocs renders the same pages into the human site; agents read the same bytes (in-repo via git, remote via the docs site). No second production path — one rendered truth, verified by one render check.

Docstrings are the single source of truth. The generator is the only formatter (structure → markdown, one dialect: python-markdown + mkdocs extensions). Markdown joints are managed deliberately: blank line after every emitted piece, fences balanced within one emit.

## Decisions and rejected alternatives

- **pdoc → griffe (done).** pdoc's `docstrings.google()` emits pre-rendered markdown in markdown2 dialect; the first version regex-patched it for python-markdown. Griffe hands over structured sections instead, so all patch shims were deleted. Bonus: static defaults render as source text (`src: pl.Expr = CLOSE`), re-export docstrings resolve, dataclass params come out clean.
- **griffe2md — rejected after pilot.** Default output ~7.5x bloat (inherited members, attributes); tuned config gets ~80% there but Examples sections render broken without reforming docstrings to doctest style, base-class anchors are dead, and a driver script survives anyway. General-purpose renderer vs house style hardcoded — we own ~200 lines instead.
- **mkdocstrings — parked.** HTML-only output kills the committed-md deliverable (agents), imports the same Examples docstring reform to the human site, and adds a plugin stack. Revisit trigger: real need for symbol cross-links / per-parameter anchors at scale (see Layout below).
- **griffe JSON as the agent artifact — rejected.** Order of magnitude bigger than the md, worse LLM reading terrain, poor greppability, and committed dumps churn on every source edit (embedded linenos). Reproducible on demand: `uv run griffe dump mplchart`. Publish as `site/api.json` in CI only if a mechanical consumer ever appears.
- **`.pyi`-as-docs — rejected for pure Python.** The typed source already is the machine-readable truth; shipping stubs beside typed source makes checkers ignore inline annotations. Stubs are the right format only where source is unreadable (mintalib's Cython core, which already has them).
- **Decoupling human docs (mkdocstrings) from agent docs (md) — declined.** The LLM-format dividend is marginal (markdown for humans ≈ markdown for LLMs); two production paths mean drift. The agent side is independent of the human rendering anyway (see Discovery), so the option stays open at no cost.

## Discovery layer

**v1 (done):**

- `scripts/mkdocs_hooks.py` — post-build hook copying every documentation `.md` into the site output. `use_directory_urls` renders a page to `<stem>/index.html`, leaving `<stem>.md` free beside it — the URL the `.md` convention already predicts. With `docs/index.md` linking the reference pages and those linking each other, the whole doc set is navigable as markdown on one origin, which is what agents can actually follow.
- No project `llms.txt` (2026-08-16, after ~3 weeks of having one). It was generated by `make-api-docs.py` and committed under `docs/`, and it turned out to be a text rendering of the nav: an index restating `index.md` and the Reference section. The decisive point is discovery — nothing auto-fetches `/mplchart/llms.txt`; tools that support the convention fetch the *origin root*, so the only file with automatic reach is `furechan.github.io/llms.txt` (hand-written, in the user-site repo, pointing at each project's `index.md`). Generating it at build time instead of committing it was considered and rejected: it fixes drift by making the artifact invisible. What the exercise did produce, and what was kept, is the `.md` publishing above and the missing reference links in `index.md`.
- In-repo pointer (done): `CLAUDE.md` "Docs and notes" section documents the generated reference, `inv apidocs`, and the do-not-hand-edit rule (the repo has no `AGENTS.md`; if one is created later via `/sync-agents-md`, the pointer flows in from CLAUDE.md).

**v2 — post-build hook done (see above); still only if wanted later:** generating `llms-full.txt` (whole corpus: intro + reference + notebook text via nbconvert with outputs stripped — base64 images must be excluded). Corpus is ~35-45k tokens, well under the ~500KB practical ceiling for llms-full. Same caveat as above: it would only be reachable if something linked it.
- No repo-root llms.txt: AGENTS.md covers in-repo agents, README covers the GitHub landing page, llms.txt is a web-root convention — and the web root is `furechan.github.io`, not this repo.

## Discovery matrix (who finds the reference how)

| Scenario | Path |
|---|---|
| Agent in this repo | AGENTS.md → `docs/reference/*.md` (one Read, no network) |
| Agent in a sibling project, clone exists | `~/Projects/mplchart/docs/reference/*.md` |
| Known env, no clone | docs site → llms.txt → raw md |
| Outsider, package installed | `site-packages` source first (version-correct!), then dist-info Project-URLs → docs site |
| Outsider, nothing | search → PyPI/GitHub/site → docs site → llms.txt → md |

Rule: local beats remote; among remote, indexed markdown beats raw-repo beats HTML; site for API/usage questions, repo for implementation/history/unpublished.

## Layout escalation ladder

If the reference pages' look stops pleasing: (1) edit the render functions — we emit every character, a layout change is one function + `inv apidocs`; (2) enable richer markdown (pymdownx.details for collapsible sections, admonition boxes for EXPERIMENTAL notes, attr_list); (3) scoped CSS via `extra_css`; (4) only for mkdocstrings-specific chrome (cross-linked types, parameter anchors): revive the parked decoupling — human pages via mkdocstrings, committed md stays for agents, llms.txt/AGENTS.md unchanged.

## mintalib port

Copy and customize; probes (July 2026) confirmed: `force_inspection=True` gives full docstrings + typed params for `functions`/`indicators`/`expressions` (runtime-attached); `core` docstrings come through but typed signatures need the `.pyi` stub dance (port the ~20-line stub-parse helper from its existing pdoc script, or accept untyped core signatures — the docstrings carry the types).

Sharing discipline: renderer functions byte-identical in both repos; all differences confined to the config head (`PACKAGE`, `MODULES`, loader flags, stub helper). Promote the renderer to a small package under `~/Projects/python-dev/packages` (nbcheck-style) only when a fix must be applied twice and that annoys, or a third repo appears.

## Loose ends

- pdoc is still in dev deps but unused by the script (predates this work) — remove if not otherwise wanted (`uv remove --dev pdoc`).
- `inv apidocs` is not part of `inv check`; docstring edits require remembering to regenerate (the render check runs inside apidocs, and diffs surface in review). Could add a staleness check to `check` later.
